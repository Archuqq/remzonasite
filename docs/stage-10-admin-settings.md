# Этап 10 — Админка: настройки сайта

## 1. Что сделано

- Реализована страница `/admin/settings` с редактированием всех публичных настроек сайта.
- Телефон проверяется как российский номер, а `phone_href` автоматически пересчитывается на сервере.
- Добавлен переключатель публикации отзывов; после сохранения изменения сразу влияют на публичный сайт.
- Dashboard `/admin` показывает число опубликованных услуг, телефон и статус отзывов.
- Добавлен защищённый API `GET/PUT /api/admin/settings` с CSRF-проверкой и Zod-валидацией.
- Кэш настроек и публичный путь сбрасываются после успешного сохранения.

## 3. Как это работает

Страница настроек — Server Component. Она вызывает `getSettings()` и передаёт сериализованный `SiteSettings` в клиентский `SettingsForm`. Форма отправляет JSON через `PUT /api/admin/settings`, блокирует повторное сохранение и показывает успех или ошибку.

API перед изменением вызывает `guardAdminMutation`, поэтому проверяются JWT-сессия администратора и same-origin/CSRF-заголовки. Тело проверяется через `siteSettingsSchema`.

После успешной проверки телефон проходит `normalizeRussianPhone`:

- допускаются цифры, пробелы, `+`, скобки и дефисы;
- формат `8XXXXXXXXXX` переводится в `7XXXXXXXXXX`;
- формат из 10 цифр получает префикс `7`;
- итог должен содержать ровно код страны `7` и 10 цифр;
- в БД записывается `phone_href = tel:+7XXXXXXXXXX`.

Клиент не может передать `phoneHref` напрямую. API принимает только отображаемый телефон и вычисляет ссылку самостоятельно.

`updateSettings()` атомарно upsert-ит все известные ключи `Setting`, затем вызывает `revalidateTag("settings", "max")` и `revalidatePath("/")`. Поэтому Header, Footer, Hero, карточки услуг, карта, CTA и секция отзывов получают новые значения при следующем публичном рендере.

### Влияние полей

| Поле формы | Ключ `Setting` | Влияние |
| --- | --- | --- |
| Телефон | `phone` | Видимый номер в Header, Footer, карте, Hero и CTA. |
| Ссылка для звонка | `phone_href` | Только отображение вычисленного `tel:` значения; вручную не редактируется. |
| Адрес | `address` | Footer, карточка карты, поиск и ссылка маршрута. |
| Часы работы в будни | `hours_weekdays` | Footer и карточка карты. |
| Часы работы в выходные | `hours_weekend` | Footer и карточка карты. |
| ID организации Яндекс | `yandex_org_id` | URL iframe отзывов и ссылки на отзывы; значение по умолчанию `73425839561`. |
| Показывать отзывы на сайте | `reviews_enabled` | При `false` сервер не рендерит `ReviewsSection`, iframe и якорь `#reviews`; Header и Footer также не показывают ссылку «Отзывы». |
| SEO-название сайта | `site_name` | Хранится как единое название для последующего SEO-слоя; текущая metadata будет окончательно подключена на этапе 11. |

### Dashboard

`/admin` параллельно читает `getSettings()` и считает `Service` с `isPublished=true`. Отображаются опубликованные услуги, текущий телефон и статус отзывов. Если опубликованных услуг нет, показывается сообщение «Услуг пока нет — добавьте первую в разделе «Услуги».».

## 4. Интерфейсы

Все маршруты требуют администратора. Изменяющий запрос дополнительно требует same-origin заголовки.

### `GET /api/admin/settings`

Успех `200`:

```json
{
  "settings": {
    "phone": "+7 (900) 000-00-00",
    "phoneHref": "tel:+79000000000",
    "address": "г. Серпухов, Советская улица, 2кА",
    "hoursWeekdays": "Пн–Пт: 09:00–20:00",
    "hoursWeekend": "Сб–Вс: 10:00–20:00",
    "yandexOrgId": "73425839561",
    "reviewsEnabled": true,
    "siteName": "РЕМЗОНА"
  }
}
```

Ошибки: `401` без сессии администратора.

### `PUT /api/admin/settings`

Тело JSON:

```json
{
  "phone": "+7 (900) 000-00-00",
  "address": "г. Серпухов, Советская улица, 2кА",
  "hoursWeekdays": "Пн–Пт: 09:00–20:00",
  "hoursWeekend": "Сб–Вс: 10:00–20:00",
  "yandexOrgId": "73425839561",
  "reviewsEnabled": true,
  "siteName": "РЕМЗОНА"
}
```

Успех `200`: `{ "settings": SiteSettings }`, включая рассчитанный `phoneHref`.

Ошибки:

- `400` — невалидный JSON, номер, ID или поле; ответ содержит `error` и при валидации `fields`;
- `401` — нет валидной админской сессии;
- `403` — запрос не прошёл same-origin/CSRF-проверку.

### Компоненты

```ts
SettingsForm({ settings: SiteSettings }): JSX.Element
```

## 6. Принятые решения и отклонения от плана

- Для совместимости с существующей админкой использован JSON API и клиентский `fetch`, а не Server Action.
- `phone_href` нельзя редактировать вручную: это исключает рассинхронизацию видимого номера и ссылки.
- `site_name` уже сохраняется и возвращается API, но использование в metadata оставлено этапу 11.
- Dashboard больше не перенаправляет сразу в услуги, чтобы показывать требуемый краткий обзор.

## 7. Как проверить

1. Запустить MySQL, применить миграции и seed, затем открыть `/admin/login`.
2. Перейти в `/admin/settings`: должны загрузиться телефон, адрес, часы, ID `73425839561`, SEO-название и включённый переключатель отзывов.
3. Изменить телефон на `8 (900) 111-22-33`, сохранить и убедиться, что отображаемое значение `phoneHref` стало `tel:+79001112233`.
4. Ввести некорректный номер или буквы: API должен вернуть `400` с понятной ошибкой.
5. Выключить «Показывать отзывы на сайте», сохранить и открыть `/`: секция отзывов, iframe, якорь и ссылки «Отзывы» должны исчезнуть.
6. Включить отзывы обратно и проверить их появление после обновления публичной страницы.
7. Открыть `/admin`: проверить число опубликованных услуг, телефон и статус отзывов.
8. При отсутствии опубликованных услуг проверить пустое состояние dashboard.
9. Проверить без cookie: `GET /api/admin/settings` должен вернуть `401`.
10. Выполнить `npm run lint`, `npm run typecheck`, `npm run build`.

## 8. Ограничения и что нужно знать на следующих этапах

- Реальный CRUD и переключение настроек требуют доступного MySQL; статическая сборка не заменяет ручную проверку.
- Кэш `getSettings()` сбрасывается тегом `settings`, а публичная страница дополнительно инвалидируется через `/`.
- `site_name` подготовлен для SEO, но итоговые metadata, JSON-LD, robots и sitemap относятся к этапу 11.
- Адрес и ID Яндекс валидируются по длине и формату, но существование организации в Яндекс Картах отдельно не проверяется API.
