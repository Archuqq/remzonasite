# Этап 8 — Секции: процесс, преимущества, отзывы

## 1. Что сделано

- На главную добавлены секции «Простой и понятный цикл» и «Наши преимущества».
- Процесс содержит пять этапов 01–05 и адаптируется с горизонтальной схемы на desktop к вертикальной на mobile.
- Преимущества выведены четырьмя элементами с иконками Lucide и адаптивной сеткой 1 / 2 / 4 колонки.
- Отзывы подключены официальным iframe-виджетом Яндекс Карт с ленивой загрузкой.
- Секция отзывов, якорь и пункт меню не рендерятся при выключенном `reviews_enabled`.
- Документация и карта проекта обновлены; API и схема БД не изменялись.

## 3. Как это работает

`HomePage` остаётся серверным компонентом и получает `settings` через `getSettings()`. После `ServicesSection` он рендерит `ProcessSection`, `AdvantagesSection`, а затем `ReviewsSection`.

### Процесс

`processSteps` из `src/content/process.ts` имеет тип:

```ts
type ProcessStep = {
  number: string;
  title: string;
  description: string;
};
```

Массив не читается из БД. `ProcessSection` использует `Section` и `Reveal`; на desktop элементы стоят в пять колонок с тонкой верхней линией и стрелками, на mobile переходят в вертикальный список с линией слева.

### Преимущества

`advantages` из `src/content/advantages.ts` имеет тип:

```ts
type Advantage = {
  icon: LucideIcon;
  title: string;
  description: string;
};
```

Изменение текста выполняется напрямую в этом файле. Иконки являются компонентами `lucide-react`, отображаются в белой круглой подложке с рамкой `#E5E7E8`. Якорь `#about` находится на `Section`.

### Отзывы

`ReviewsSection({ enabled, yandexOrgId })` возвращает `null`, если `enabled === false`. При `true` создаются секция с `id="reviews"`, заголовок и `ReviewsWidget`.

`ReviewsWidget` строит iframe URL:

```text
https://yandex.ru/maps-reviews-widget/{yandexOrgId}?comments
```

Для seed-настройки это `https://yandex.ru/maps-reviews-widget/73425839561?comments`. iframe имеет `loading="lazy"`, фиксированную высоту `420px` и заголовок для доступности. Под iframe постоянно доступна резервная ссылка на страницу отзывов организации в Яндекс Картах. Это позволяет перейти к отзывам при блокировщике или недоступности iframe.

Флаг берётся из `settings.reviewsEnabled`, который формируется в `src/lib/settings.ts` из строки `Setting.reviews_enabled`. `getSettings()` кэшируется тегом `settings`; этап 10 сбрасывает этот тег после изменения настроек.

Header и Footer уже получают тот же `reviewsEnabled` и условно выводят пункт «Отзывы». Поэтому при `false` не выводятся ни блок секции, ни якорь, ни ссылки меню.

## 4. Интерфейсы

Новых HTTP API и таблиц БД нет.

### Компоненты

```ts
ProcessSection(): JSX.Element
AdvantagesSection(): JSX.Element
ReviewsSection({
  enabled: boolean,
  yandexOrgId: string,
}): JSX.Element | null
ReviewsWidget({
  enabled: boolean,
  yandexOrgId: string,
}): JSX.Element | null
```

Источники настроек:

- `reviews_enabled` → `SiteSettings.reviewsEnabled`;
- `yandex_org_id` → `SiteSettings.yandexOrgId`.

## 5. Переменные окружения и команды

Новых переменных окружения нет. Используются существующие `DATABASE_URL` и настройки таблицы `Setting`.

```bash
npm run lint
npm run typecheck
npm run build
```

Для ручной проверки нужен запущенный MySQL с применёнными миграциями и seed.

## 6. Принятые решения и отклонения от плана

- Процесс и преимущества оставлены статичными TypeScript-массивами, как требует план; редактору сайта не нужно менять их через админку.
- Отзывы не копируются в HTML: используется официальный iframe URL Яндекс Карт.
- В качестве резервного сценария используется обычная ссылка на страницу отзывов, потому что серверный iframe не позволяет надёжно определить блокировку внешнего виджета из браузера.
- Якорь отзывов создаётся только внутри включённой `ReviewsSection`, а не отдельным пустым контейнером.
- Поле `yandexOrgId` передаётся из настроек, поэтому смена ID не требует изменения компонента.

## 7. Как проверить

1. Запустить MySQL, применить миграции и seed, затем выполнить `npm run dev`.
2. Открыть `/`: после услуг видны «Простой и понятный цикл», «Наши преимущества», затем «Нам доверяют».
3. Проверить пять этапов процесса: на desktop они расположены в ряд со стрелками, на mobile — вертикально.
4. Проверить четыре преимущества: desktop — четыре в ряд, tablet — два в ряд, mobile — один или два в ряд в зависимости от ширины.
5. В DevTools проверить iframe: `loading="lazy"`, высота зарезервирована, URL содержит `maps-reviews-widget/73425839561?comments`.
6. Перейти по ссылке «Открыть все отзывы на Яндекс Картах» и убедиться, что открывается страница организации с отзывами.
7. Установить `reviews_enabled=false` через настройки БД или админку: секция, `#reviews`, пункт «Отзывы» в Header и Footer должны исчезнуть после сброса кэша настроек.
8. Проверить `prefers-reduced-motion`: контент остаётся видимым без задержки анимации.
9. Выполнить `npm run lint`, `npm run typecheck`, `npm run build`.

## 8. Ограничения и что нужно знать на следующих этапах

- iframe зависит от доступности домена `yandex.ru` и может блокироваться расширениями или политикой Content Security Policy; резервная ссылка остаётся доступной.
- Автоматические визуальные проверки разных viewport и Lighthouse на этом этапе не выполнялись.
- Секция контактов и карта всё ещё представлены заглушкой до этапа 9.
- Контент процесса и преимуществ не редактируется из админки: меняйте `src/content/process.ts` и `src/content/advantages.ts`, затем пересобирайте приложение.
- При изменении `yandex_org_id` нужно убедиться, что организация имеет доступный виджет отзывов по новому ID.
