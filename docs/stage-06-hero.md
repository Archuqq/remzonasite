# Этап 6 — Hero: главный экран

## 1. Что сделано

- Главная получила серверный Hero с трёхстрочным H1, подзаголовком, CTA-звонком, ссылкой на услуги и тремя преимуществами.
- Подключены AVIF/WebP srcset 640/1024/1600/1920, high-priority responsive preload и blur placeholder.
- На desktop/tablet изображение занимает full-bleed фон, а светлый градиент защищает текст слева; на mobile текст идёт первым, фотография — после него.

- Файл `assets-source/hero-mercedes.png` не изменялся.

## 3. Как это работает

`Hero({ phone, phoneHref })` — серверный компонент. `page.tsx` уже получает настройки через `getSettings()` и передаёт `phone`/`phoneHref`; Hero не читает БД и не добавляет клиентский JavaScript.

Порядок содержимого:

1. Верхняя подпись «АВТОСЕРВИС ПРЕМИУМ-КЛАССА» с небольшим акцентным маркером.
2. H1 «Сервис, которому / можно доверить / автомобиль».
3. Описание из спецификации.
4. `PhoneLink` с текстом «Позвонить» и secondary-якорь `#services`.
5. Три преимущества с lucide-иконками: оборудование, мастера, гарантия.
6. Фото Mercedes внутри `<picture>`.

Изображение загружается eager с `fetchPriority="high"`, `decoding="async"`, явными `width=1920` и `height=1081`. AVIF source идёт первым, затем WebP source и WebP fallback. Один набор srcset применяется для AVIF/WebP:

```text
/images/hero-640.{avif,webp} 640w
/images/hero-1024.{avif,webp} 1024w
/images/hero-1600.{avif,webp} 1600w
/images/hero-1920.{avif,webp} 1920w
```

`imageSizes` — `100vw`, поскольку на tablet/desktop кадр full-bleed на ширину viewport, а на mobile занимает ширину контентной колонки. React DOM `preload()` вызывается серверным компонентом с `as: "image"`, `type: "image/avif"`, `imageSrcSet`, `imageSizes` и `fetchPriority: "high"`; браузер может выбрать ресурс по тому же responsive набору, что и `<picture>`. Blur data URL лежит в фоне контейнера до декодирования выбранного изображения.

### Композиция по ширинам

- **Mobile (<768 px):** copy размещён первым. Кнопки занимают всю доступную ширину; фото идёт отдельным кадром 16:9 ниже текста. На изображение не накладывается текст.
- **Tablet (768–1279 px):** hero имеет минимальную высоту 620 px; фото лежит на весь фон. Контент ограничен шириной и занимает около 53%; светлый градиент обеспечивает читаемость и визуально оставляет фото справа.
- **Desktop (≥1280 px):** hero имеет минимальную высоту 680 px; copy занимает около 48% доступной ширины, изображение full-bleed, `object-position` смещён на 58% для баланса автомобиля и вывески. Градиент непрозрачен под текстом и уходит в прозрачность вправо.

Фотография уже содержит вывеску «РЕМЗОНА / АВТОСЕРВИС». Снимок сохранён без изменений; требуемая полная формулировка «АВТОСЕРВИС ПРЕМИУМ-КЛАССА» остаётся верхней подписью над H1.

## 4. Интерфейсы

HTTP API этапа нет.

```ts
Hero({ phone: string, phoneHref: string }): JSX.Element
```

Пропсы приходят из `SiteSettings`. `phoneHref` используется для прямого `tel:` перехода через `PhoneLink`; `phone` задаёт доступное имя/текст ссылки. Ссылка «Наши услуги» ведёт на `#services`.

## 5. Переменные окружения и команды

Новых env-переменных нет. `phone` и `phone_href` читаются из таблицы `Setting` через `getSettings()`. Если номер меняется в админке, кнопка Hero получает актуальный `tel:` адрес после revalidation тега настроек.

Пересоздать responsive media из исходника:

```bash
npm run images:hero
```

Команда генерирует четыре WebP и четыре AVIF в `public/images/`, а также blur data URL в `src/lib/hero-blur.ts`.

## 6. Принятые решения и отклонения от плана

- CTA «Записаться на сервис» заменён на «Позвонить» (`PhoneLink` / `tel:` из настроек) — требование заказчика.
- Фото Mercedes не редактировалось: на стене «РЕМЗОНА / АВТОСЕРВИС»; полная подпись «АВТОСЕРВИС ПРЕМИУМ-КЛАССА» только в тексте над H1.
- На desktop/tablet фото full-bleed под градиентом, а не отдельная колонка 45/55 в grid: так автомобиль и вывеска остаются в кадре, текст читается слева. На tablet визуальный баланс близок к 45/55 за счёт ширины текстового блока (~53%).
- Preload через `react-dom` `preload()`, а не сырой `<link>` в JSX: Next 16 так выводит `imagesrcset`/`imagesizes`.
- Замеры Lighthouse в момент реализации этапа 6 не удалось получить без браузерного прогона; целевой LCP ≤ 2.5 с. Повторная проверка — вместе с секцией услуг (этап 7), если доступен `/`.

## 8. Ограничения и что нужно знать на следующих этапах

- `src/app/(site)/layout.tsx` остаётся `force-dynamic`: шапка читает настройки. Данные Hero-телефона идут из `getSettings()` с тегом `settings`.
- Якорь `#services` должен существовать у секции услуг (этап 7).
- Responsive-файлы пересобираются только `npm run images:hero`; PNG в `assets-source/` не трогать.
- Не подключать форму записи к кнопкам Hero.

## 7. Как проверить

1. Запустить MySQL 8 и выполнить миграции/seed по [документации этапа 1](stage-01-database.md), затем `npm run dev`.
2. Открыть `/`, проверить подпись, точный H1, текст, две кнопки и преимущества. «Позвонить» должен иметь актуальный `tel:` href, «Наши услуги» — `#services`.
3. Проверить viewport 375, 768, 1024, 1280, 1440 и 1920 px: mobile — сначала текст и затем фото; tablet — приблизительно 45/55; desktop — текст слева и полнокадровая фотография справа/на заднем плане; не должно быть горизонтального скролла или перекрытия H1.
4. Проверить DOM: AVIF source, WebP source, fallback, width/height, `fetchpriority="high"`, `loading="eager"` и responsive preload link с `imagesrcset`/`imagesizes`.
5. Запустить `npm run images:hero` и сравнить результаты с исходниками; исходный PNG не должен меняться.
6. Запустить `npm run lint`, `npm run typecheck`, `npm run build`.

### Производительность и Lighthouse

Размеры изображений получены генератором на этапе 2 из PNG 1671×941:

| Width |     WebP |    AVIF |
| ----- | -------: | ------: |
| 640   |  36.3 KB | 21.2 KB |
| 1024  |  70.3 KB | 42.1 KB |
| 1600  | 125.4 KB | 74.3 KB |
| 1920  | 147.4 KB | 90.0 KB |

На 1600 выбранный AVIF равен 74.3 KB, WebP fallback — 125.4 KB; браузер загружает один формат/размер, а blur data URL занимает около 0.1 KB. `width`/`height`, eager high-priority load и responsive preload направлены на CLS≈0 и уменьшение LCP.

Фактический Lighthouse mobile measurement в этой среде не выполнен: на `127.0.0.1:3306` нет MySQL, поэтому публичный `/` возвращает 500 при `getSettings()`; также Lighthouse CLI и локальный Chrome/Chromium не установлены. Следовательно, LCP/CLS/Performance score не заявляются как измеренные. После запуска БД выполнить Lighthouse на `/` и записать реальные значения; целевой LCP остаётся ≤2.5 s.
